# MIKU: что изменилось в `feature/miku` относительно `main`

Срез: `feature/miku` (`001550b`) против `origin/main` (`e19261f`).
Общий объём: **15 коммитов, 97 файлов, +12 941 / −77 строк**.

```bash
git diff --stat origin/main...feature/miku
git log --oneline origin/main..feature/miku
```

---

## 1. Зачем ветка

`main` — это личный медиакаталог: он ищет и показывает то, что уже лежит в библиотеке. Ветка добавляет слой, который **отвечает и действует**. Ассистент MIKU живёт во встроенной панели, видит каталог через поисковый индекс, помнит факты о пользователе, выполняет действия через объявленные интеграции модулей и выполняет их в отдельном изолированном процессе, а каждое изменение показывает в журнале с возможностью отмены.

Ключевое ограничение, которое определило всю конструкцию: **модули не импортируют друг друга**. Ассистент видит другие модули только через типизированные контракты и реестр интеграций. Всё, что ниже, — следствие этого правила.

---

## 2. Что появилось

### 2.1 Изолированный runtime агента (`app/core/agent/`)

Новый сервис `agent-runtime` (`app/core/agent_runtime.py`, 325 строк) вынесен из web-процесса. Причина практическая: каскад с внешними вызовами и выводами модели не должен иметь доступ к Postgres и Redis, иначе падение или зависание модели уронит сайт.

- **Контракт наружу — три ручки** вместо доступа к БД: `GET /internal/agent/catalog`, `POST /internal/agent/invoke`, `GET /internal/agent/resources/{id}` (`app/core/agent_router.py`).
- Web говорит с ним только по bearer-токену, каскад ходит в модули по `X-Agent-Key`.
- Провайдеры настроек живут в БД на стороне web, в sidecar попадают настройками на вызов: `app/core/agent/model.py` (208 строк, OpenAI-совместимый чат, tool calls, `finish_reason=tool_calls` как сигнал продолжения) и `app/core/agent_client.py`.
- `app/core/agent/engine.py` (580 строк) — сам каскад: бюджет шагов, лимит глубины, очередь для повторяемых шагов, заземление на найденных документах.
- `app/core/agent/primitives.py` — вызов интеграции по id с валидацией схемы и нормализованными ошибками (`IntegrationServiceError`, `IntegrationRejectedError`, `IntegrationUnavailableError`).
- Права выдаются не по факту наличия интеграции, а по декларации: `AGENT_CONSUMER_ID` (по умолчанию `miku`) определяет, какие интеграции вообще видны.

### 2.2 Каскад с журналом и отменой

`app/modules/miku/cascades.py` (292 строки) — не «лог для истории», а механизм отката. Каждое изменение, сделанное агентом, записывается шагом с обратным действием; `POST /api/miku/cascades/{id}/undo/{step}` откатывает шаг. Откат — обычная интеграция, а не специальный код в UI.

- Новый общий контракт `app/contracts/undo_v1.py` (`UndoRequest` / `UndoResult`).
- `IntegrationEffects` в `app/core/module_types.py` научился объявлять `reversible` и `undo_integration`. Обратите внимание на смысл: обратимость **не блокирует** действие. Агент может писать сам, приложение лишь предлагает отмену после.
- Попутно в `app/core/modules.py` появилась нормализация исключений: любое неожиданное исключение интеграции теперь превращается в `IntegrationServiceError`, а не всплывает как `KeyError` с внутренним трейсбеком.

### 2.3 Память (`miku.memory.*.v1`)

`app/modules/miku/integrations.py` (222 строки) — три инструмента, а не команды: модель сама решает, что запомнить.

| Интеграция | Действие | Обратимость |
|---|---|---|
| `miku.memory.write.v1` | сохранить/забыть факт (`profile` с ключом или `episodic` с сводкой) | да, через `miku.memory.undo.v1` |
| `miku.memory.search.v1` | найти сохранённое | — |
| `miku.memory.undo.v1` | забыть то, что записал предыдущий write | — |

Таблицы `miku_profile_memory` / `miku_episode_memory` со своими Alembic-историями внутри пакета модуля.

### 2.4 Приватный поисковый индекс (новый модуль `search`)

Модуль `search` (`app/modules/search/`, 4 файла + 2 миграции) индексирует документы модулей и отдаёт `search.global.v1` — один способ найти что угодно, вместо того чтобы ассистент угадывал интеграцию каждого модуля.

- `app/modules/search/integrations.py` (553 строки) — построение индекса, outbox для синхронизации, выдача.
- Индекс приватный: поиск идёт по Postgres, а не наружу.
- Подписка на события модулей: `app/modules/search/events.py`.

### 2.5 Контракты, через которые модули открываются наружу

`app/contracts/` — единственный разрешённый способ узнать о чужом модуле:

- `search_query_v1.py`, `search_documents_v1.py` — поиск и индексация;
- `miku_memory_v1.py` — память;
- `undo_v1.py` — откат;
- `vault_capture_v1.py` — захват из vault (новое);
- `library_viewer_v1.py`, `video_source_catalog_v1.py` — расширены.

Существующие модули получили тонкие адаптеры, а не новые API: `alllib`, `music`, `video_archiver`, `vault`, `youtube` — файлы `search.py` и правки `integrations.py`/`module.py`. Например, `library.viewer.v1` в `alllib` теперь умеет `operation: "search"`, а объявлен он только для серверного разрешения ресурсов и **скрыт** от модели (`runtime_tools()`), чтобы поиск всегда шёл через `search.global.v1`, а не через догадку.

### 2.6 UI

- `static/miku-assistant.js` (778 строк) — виджет ассистента: WS, REST-fallback, отмена, barge-in, озвучка, запись голоса.
- Виджет встраивается в `app/core/templates/base.html` и рисуется через `textContent` — `innerHTML` в скрипте нет, значения из сети не интерполируются в разметку.
- `app/modules/miku/templates/miku_dashboard.html` (404 строки) — настройки провайдеров, память, журнал изменений, отмена.
- `app/modules/video_archiver/templates/video_dashboard.html` — элемент, который открыл ассистент, теперь помечается `data-video-id`, чтобы подсветить источник. Заодно убран двухсекундный `setTimeout` перед показом плеера.

### 2.7 Локальная модель и Compose

- `miku-llm` в `docker-compose.yml` — CPU-сервис с локальной GGUF-моделью; `docker-compose.gpu.yml` — GPU-профиль.
- `model-init` скачивает веса один раз в `storage/models`, `model-control`/`agent-control` — профили `./start.sh`.
- Сетевые изоляции: `agent-egress` — единственная сеть, у которой есть выход наружу для провайдеров; `agent-control` — внутренняя.
- Валидация в `app/core/config.py`: при `AGENT_RUNTIME_ENABLED=1` токен runtime обязан быть не короче 32 символов.

### 2.8 Наблюдаемость

`app/core/observability.py` — Redis-полотно продублировано в stdout, и запись лога об ошибке хода агента уходит в stdout. Причина конкретная: ошибка провайдера была видна только в Redis, и при работе в контейнере её нельзя было увидеть вообще.

## 3. Что исправлялось (три `fix`)

| Коммит | Дефект | Причина |
|---|---|---|
| `d83b47c` | Провайдер не вызывался, ошибки глохли | Базовый URL `https://api.weegam.com/uni/v1` не дополнялся до `/chat/completions`; нестроковые настройки роняли ход; логи не попадали в stdout |
| `f54e9ab` | «Что я люблю?» не находило «люблю пиццу» | Сопоставление было только по подстроке, русские падежи гарантируют промах |
| `001550b` | `Failed to fetch` при отправке | После рестарта контейнера вкладка держит мёртвое соединение; браузер не повторяет `POST` и показывает сетевую ошибку при живом сервере |

Третий — самый показательный: сервер был полностью исправен (`POST /api/miku/query` → `200`), а пользователь видел сетевую ошибку. Поэтому REST-вызовы теперь повторяются один раз с отключённым кешем, сокет поднимается параллельно, а настоящий сбой сообщается как «Нет связи с сервером».

## 4. Общий текстовый матчинг

`app/core/text_match.py` (86 строк) вынесен в `core`, потому что его используют и память, и поиск. Правило: общий префикс из трёх букв покрывает большинство окончаний, всё остальное требует четырёх совпадающих букв и реальной похожести. Совпадение остаётся «любое слово», а не «все слова»: вопрос — это перефраз, и требование полного совпадения теряло бы факт при любой перестановке слов. `app/modules/search/integrations.py` делегирует тому же правилу, чтобы память и поиск не разъехались.

## 6. Как развернуть

```bash
uv sync --locked --all-extras
./start.sh                 # web, worker, postgres, redis, agent-runtime, browser, miku
./start.sh --miku-local    # плюс локальная модель
```

Переменные окружения (.env.example): `MIKU_LLM_*`, `MIKU_STT_*`, `MIKU_TTS_*`, `AGENT_RUNTIME_ENABLED`, `AGENT_RUNTIME_TOKEN`, `AGENT_INTERNAL_KEY`, `AGENT_CONSUMER_ID`, `MIKU_MODEL_*`, `MIKU_LLM_THREADS/CPUS/CTX`.

Маршруты ассистента: `/miku/dashboard`, `/api/miku/{capabilities,runtime,query,transcribe,speech,memory,cascades,providers}`, `/api/miku/ws`.

## 7. Замечание по ревью

`app/modules/miku/ARCHITECTURE.md` описывает устройство runtime подробнее; этот документ фиксирует именно **диф относительно `main`**. При слиянии стоит проверить: не конфликтует ли `AGENT_RUNTIME_TOKEN`-ротация в `start.sh` с уже созданным `.env` у пользователей, и остаётся ли `library.viewer.v1` скрытым для модели во всех путях discovery.
